The route takes `preview` and `github: { owner, repo }`. A request the preview environment does not recognise is answered 404 on every route; `GET {basePath}/context` names the session, and the pull request (`pullRequest` number and `pullRequestUrl`, null without a number or a `github` option) when the reviewer has linked GitHub: the stated pull request while it is open, then the stated `MAPLE_BRANCH` head, then the commit, then the head branch named exactly the key, then the preview's `matches`. A pull request GitHub found closed is not echoed. Several matches answer 409 on reads and writes alike and write nothing; `/me` and `/auth/*` see an unresolved `request.preview` (`branch` is the stated head branch, else the key). With `githubAuth` and no `store`, comments go to the resolved pull request under the reviewer's token, and `github.media` gives their screenshots a link. A preview identified only by what a request carries, or with no `MAPLE_PREVIEW_KEY`, logs one warning per handler through `logger`.

`IdentityRequest` gains an optional `preview` (`PreviewInfo`: key, label, branch, commit, pullRequest) that the route sets for per-request `store`, `media`, `gate` and `identity` callbacks, so a host never re-reads headers.

Breaking: the session cookie's `Path` now follows `basePath` unless `githubAuth.path` is set, and `PullLookup.matches` throws `AmbiguousPullError` when several open heads match, where the newest used to win. A commit lookup now counts open pull requests only. A commit in several open pull requests (a stack) prefers the one whose head is the stated branch or the key, then falls to the key's own head and `matches`, and is ambiguous only if those are too. `PullCache` now holds a `PullMatch` per token for five minutes (`POSITIVE_TTL_MS`), and remembers "none", an ambiguous match and a 401, 403 or 404 for 15 seconds per token. `PullLookup` gains `openOnly`, which the preview route sets so a closed pull request is never resolved there; a store without it still falls back to a closed one. `request.preview.pullRequest` is left out when the stated number was found closed or ambiguous.
